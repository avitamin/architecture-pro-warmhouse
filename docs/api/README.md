# API телеметрии, управления и автоматизации

Проектируемые контракты задания 4, версия 1.0.0. Сервисы ещё не реализованы. Исходная архитектура и предметная модель: [задание 2–3](../../README.md#задание-2-проектирование-микросервисной-архитектуры). HTTP API существующего монолита в `apps/` не является реализацией этих контрактов.

Поток охватывает конфигурацию устройств, фоновый опрос, историю измерений, правила, ручные и автоматические команды, результаты и восстановление. Предполагается, что пользователь вошёл, прибор привязан и его возможности зарегистрированы. Вход, привязка, управление домами и видео в этот срез не входят. ## Выбор типов API

HTTP/JSON через API Gateway удобен браузерному клиенту. OpenAPI описывает именно эту границу; Gateway преобразует данные в gRPC, но не переносит бизнес-правила из сервисов. gRPC/Protocol Buffers сохраняет ранее выбранные синхронные межсервисные контракты. RabbitMQ и AsyncAPI описывают задания и события, которые сохраняются и доставляются независимо от жизни HTTP-запроса. Приём команды не означает её физического выполнения.

Альтернативы: заменить gRPC внутренним REST — пересмотреть уже выбранную архитектуру; описать только HTTP — оставить неописанными задания, результаты и восстановление. Выбран полный связанный срез с отдельной документацией каждого транспорта.

Событие команды содержит **полный снимок результата** с версией: можно принять новую версию без промежуточных событий, не откатывая состояние старыми. Это дороже дельты по размеру, но исключает восстановление цепочки ради текущего статуса. Задания содержат **снимок конфигурации без секретов** с версией и сроком пригодности: шлюз не зависит от запроса в Devices перед каждым действием. Цена — допустимое устаревание до истечения срока. **Повторное включение правила — новая активация**, чтобы истинное условие могло вызвать действие после свежего измерения. Подробности ограничений — в contracts.md.

## Проверка и локальный просмотр

Требуются Node.js 22+, npm, Python 3 и `protoc` (проверено с 3.21.12). Версии npm-инструментов закреплены в package.json и package-lock.json; установка без lifecycle-скриптов. Зависимости не являются частью сервисов.

Из корня репозитория, при первом запуске (если `docs/api/node_modules` уже существует, используйте установленное окружение):

```bash
api_tmp=$(mktemp -d /tmp/warmhouse-api.XXXXXX)
cp docs/api/package.json docs/api/package-lock.json "$api_tmp/"
npm ci --prefix "$api_tmp" --ignore-scripts --no-audit --no-fund --cache "$api_tmp/npm-cache"
ln -s "$api_tmp/node_modules" docs/api/node_modules
npm --prefix docs/api run check
protoc -I docs/api/proto --include_imports --descriptor_set_out="$api_tmp/contracts.pb" docs/api/proto/warmhouse.proto
npm --prefix docs/api run build -- "$api_tmp/site"
python3 -m http.server 8765 --bind 127.0.0.1 --directory "$api_tmp/site"
```

Открыть `http://127.0.0.1:8765`. Главная страница содержит Swagger UI и выбор приложения AsyncAPI. Все библиотеки и спецификации обслуживаются локально; CDN не требуется. `Try it out` отключён: адрес `api.warmhouse.example` демонстрационный, backend не развёрнут. Просмотр AsyncAPI интерактивен по навигации, раскрытию сообщений и схем; отправку сообщений в брокер он не выполняет.

Для последующих запусков с установленными зависимостями создайте новый `api_tmp` через `mktemp -d` и выполните check, protoc, build и http.server. Сборка требует новый, ещё не существующий каталог назначения и не перезаписывает предыдущий результат. Временные каталоги автоматически не удаляются. Symlink `docs/api/node_modules` указывает на временное окружение; после его удаления пользователем понадобится заново подключить зависимости.

`check` валидирует OpenAPI, четыре AsyncAPI-приложения, все examples и отрицательные примеры схем, сверяет общий словарь полей с protobuf. `protoc` проверяет синтаксис и типы RPC. Ни одна из этих проверок не доказывает выполнение транзакций, сетевые повторы, безопасность развёртывания или работу оборудования. Сценарии отказов в [flows.md](examples/flows.md) — требования и ожидаемые результаты для будущих интеграционных тестов.
